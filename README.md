# Posture.ai – AI cyber risk manager

A browser-only cyber risk management app with Claude-powered analysis. No build step or server: it runs on GitHub Pages (or any static host).

## Features

- **Dashboard** – KPIs (active, critical, high, average inherent/residual score, overdue actions, high-risk vendors, vendor reviews due), a 5×5 likelihood × impact heat map, top risks and a category breakdown. Click any KPI tile or heat-map cell to open the risk register or vendor list filtered to exactly what it counts.
- **Risk register sections and fields** (Settings) – admins add sections such as Governance to the risk editor, with their own fields: text, long text, number, Yes / No, date or a pick list with its choices. Fields can be renamed, retyped and removed. Each section's values are saved on the risk and appear as CSV columns labelled with the section. Other is included to start with.
- **Risk register** – add, edit, delete, search, filter and sort risks. **Filters** narrows the register by category, inherent and residual risk level, treatment, owner, department, threat type, business impact, asset criticality, slippage and next review, alongside the stage filter, with a running “Showing X of Y” count (click a risk's title or Edit; on desktop it opens beside the register in a split view, like vendors). Each risk records:
  - **risk details**: title / control gap, threat description, background memo, asset and asset criticality, category, risk group, threat type and threat, data protection impact (C/I/A), business impact, ticket / project #, vulnerability ref / CVE, internal standard and NIST CSF controls;
  - **assessment**: inherent and residual likelihood and impact as named levels on the 5×5 scale, giving an **inherent risk** and a **residual risk**, each with a level (1. Low to 4. Critical) and a score out of 25 – shown in the risk, the register and the CSV export;
  - **treatment**: approach, plan / mitigating controls, log exception (risks set to Yes are listed in the **Exceptions** tab – the same records, so edits show in both), exception approved, estimated cost, remediation project, estimated completion, due date, review frequency and next review (suggested from the frequency), with slippage worked out from the dates;
  - **ownership**: risk owner and department, asset owner, delegate, BU director and VP, compliance and risk analysts, GRC manager – picked from the people directory once it has anyone in it; choosing a risk owner fills in their department, BU director and BU VP from their reporting line;
  - **workflow & governance**: lifecycle stage (1. Identified → 6. Closed), created / submitted / treatment provided / approved / completed by and date, committee review dates and notes, and a timestamped comment log. The CSV export includes every field; inherent and residual scoring; owner, status, treatment, controls and due date. Export to CSV/JSON and import from JSON.
- **Ad-Hoc Risk Assessments** – the Adhoc Risk Assessment Summary Report for one request (a piece of software or technology), following the report template: report details (request name, requestor, population, version, license type, assessment type, solution risk level, NERC CIP, AI capability, draft or final status, plus the assessment date, reviewer and risk owner), request / scope, assessment summary, software functionality, key risks noted, a recommendations / actions table (risk domain, recommendation, inherent risk level from Very Low to Very High, risk response strategy – mitigate, accept, avoid or transfer – business inputs / treatment plan details and residual risk level; **Send to risk register** turns a row into a register risk) and the next steps / implementation hand-off table (category, support team, point of contact and actions required, starting from ten standard categories). **✨ Fill with AI** in the assessment summary has Claude write it from the other sections and suggests the solution risk level, filling it in where it's blank. **Export PDF** produces the formatted report to send to the requestor – a cover with the status and risk level, the report details, each answered section, and the recommendations and hand-off tables (it opens the print dialog: choose **Save as PDF**). Search and filter by status and risk level. **Intake questionnaire for the business** (hosted mode): the assessment type (macros, software, hardware, AI, browser extension / add-in, open-source software, removable media, software upgrade, specialized access / configuration, or other) decides the intake questions, and AI capability set to Yes adds the AI questions. Save the assessment and create a link. Someone in the business opens it without an account and answers the 41 common intake questions plus the set for that type – yes/no questions take Yes, No or Not sure with details. The link works for 14 days or until they submit, and shows only the request name and the questions. Their answers wait until the analyst views them and adds them to the assessment, which keeps them with it, lists the escalation and routing triggers the yes/no answers raise (administrative access, security-control exceptions, external data transfer and so on), fills in the requestor, population, version, license type, AI capability and request / scope where those are blank, and gives them to **Fill with AI**. Assessments written with the earlier, longer template open in this layout: their findings become rows of the recommendations table and their other answers are kept on the record. Viewers can read assessments but not change them, and see only those where they're the risk owner by default.
- **Threat Risk Assessments** – geared to the NIST framework your workspace chooses, **NIST CSF 2.0** or **NIST SP 800-53 Rev. 5**. The choice is made when the workspace is created (or before the first assessment in demo mode), can be changed in **Settings**, and sets how controls are grouped and referenced: CSF categories and subcategories, or 800-53 control families and controls. Answers carry over when it changes, and completed assessments keep the framework they were completed under. Assets that use AI get an extra set of AI security and governance controls, mapped to both frameworks, when the AI questions in the asset profile are answered Yes (uses AI, can act or use tools on its own, is trained or fine-tuned with your data). Each is a control-based review of one asset in five steps: describe the asset, answer the security controls that apply, assess each control gap (threats, likelihood, treatment and likelihood after treatment), rate the worst-case business impact, which completes the risk scores, then read the summary. Controls are picked automatically from the asset profile. Completing an assessment keeps the controls it used, even if the library changes later. Analysts and above see every assessment. Because a list of gaps shows where an asset is weak, viewers see only the ones naming them as asset or risk owner, read only. The database enforces this using the name in the people directory, which only admins can change. An analyst can create a link so someone without an account can complete the worst-case impact, asset profile and controls on a separate page (`tra-form.html`). The form starts blank unless the analyst chooses to share existing answers. A link lasts 14 days and ends when answers are submitted. The analyst reviews every change before applying it, with changes that make the asset look safer highlighted, and the person can set impact ratings, which are applied with the rest of their answers, but can't see or set owners, gaps or scores.
- **People directory** (Settings) – admins import the organization's people and reporting lines from a CSV or Excel file (first and last name, email, title, department, phone, manager email or name; a sample file with a 22-person organization is in `samples/people-directory-sample.csv` and behind **Download sample file**), adding to or replacing the directory – or enter people one at a time with **+ Add person** (name, email, title, department, phone and who they report to). People can be edited (reports follow an email change) or removed (their reports move up to their manager), and the directory can be viewed as a list or an **Org chart**; reporting loops are refused. Owner fields on risks and vendors pick from the directory plus the workspace's members. Being in the directory doesn't give access to the app: the list shows who already uses it, and admins can **Invite** anyone else as a viewer with one click.
- **Company logo** (Settings) – admins and owners upload the organization's logo (PNG, JPG, WebP or SVG; large images are scaled down in the browser). It appears in the top bar, at the top of the dashboard, on the executive briefing and ad-hoc assessment PDFs, and on the vendor questionnaire page the vendor sees. It's stored with the workspace, so every member sees it.
- **Phone numbers** – every phone field (profiles, members, invitations, the people directory and its imports, vendor contacts) uses the US format with area code, (555) 555-5555, filled in as you type; extensions are kept as x123, and international numbers starting with + are left as typed.
- **✨ AI assess** – in the risk editor, Claude scores likelihood/impact, suggests a category, writes threat scenarios, and recommends prioritised controls mapped to NIST CSF 2.0 functions, plus an estimated residual score. One click applies it to the form.
- **Vendor risk assessment** – a third-party inventory with:
  - search, a residual-tier filter and **Filters** for status, criticality, data sensitivity, access, inherent tier, controls score, owner, next review, questionnaire status, open follow-ups, AI review recommendation and extra section, with a “Showing X of Y” count;
  - click a vendor's name (or Edit) to open it; on desktop it opens beside the list in a split view, so you can move between vendors without closing it, and on phones and tablets it opens full screen. Changing tabs closes it, and unsaved changes are always confirmed first;
  - an inherent tier from business criticality, data sensitivity and access level;
  - a weighted control score across 15 key controls (governance, access control, data protection, operations, incident response, resilience and supply chain), worked out from the intake questionnaire's answers – all related answers Yes → in place, all No → missing, a mix → partial; unanswered controls count as not demonstrated and N/A is excluded;
  - a residual tier (up to two levels below inherent, never below Medium if a key control – MFA, encryption, breach notification – is missing);
  - review scheduling by inherent tier (Critical 6 months, High 12, Medium 24, Low 36) with overdue flags;
  - **✨ AI vendor review** – Claude reads the profile, answers and pasted evidence (e.g. a SOC 2 summary) and returns a risk tier, Approve / Approve with conditions / Needs more information / Reject, strengths, prioritised gaps with remediation, contract clauses to require and follow-up questions to send the vendor;
  - **Related contacts** – the people you deal with at each vendor (name, state, title, email, phone), added and edited in the vendor editor;
  - **NERC vendor?** and **CIP-013 vendor?** (Yes / No) at the top of the vendor editor, shown as tags in the vendor list, with filters and CSV columns; marking a vendor CIP-013 turns on the utility supply chain questionnaire section;
  - one click to raise a Third-Party risk in the register, and CSV export.
- **Vendor intake questionnaire** (`intake.html`) – a vendor-facing security questionnaire in the style of short-form industry questionnaires such as SIG Lite (original content, not the licensed Shared Assessments SIG):
  - a company profile (contacts, ownership, how the service is delivered and hosted, software types, in-scope applications, data types, data and disaster-recovery locations, outsourced IT services, certifications, subprocessors, who contributed and who approved) and Yes / No / N/A questions with comments across 19 domains: governance, assurance, HR, assets, identity & access, data protection, privacy, application security, vulnerability management, endpoint, network, cloud, logging, incident management, resilience, physical security, subcontractors, compliance & insurance and AI;
  - **follow-on questions** that appear only when they apply (e.g. contract terms only if subcontractors handle your data, root-cause questions only if there was a breach), so they don't count against vendors they don't apply to;
  - an optional **Utility supply chain (NERC CIP-013)** section, switched on per vendor with **Extra section** in the vendor editor: incident notification and coordination, access revocation, vulnerability disclosure (including proactive timelines), software integrity and remote access;
  - **follow-up questions**: on any answer needing attention, click **Ask follow-up**, then **Send follow-ups to vendor**, which saves the vendor and copies their link (in demo mode it downloads a file for them instead). The vendor opens the link, sees each question under the answer it's about, replies (and can change the answer), and submits. Their replies are added to each thread – changed answers are noted – and you resolve the thread or ask again. Open follow-ups show on the vendor list, and the AI vendor review reads every thread, treating replies that don't answer the question as gaps;
  - **your own version** (Settings → **Vendor questionnaire**, admins and owners): reword the built-in questions, turn off the ones you don't need (turning one off also turns off its follow-on questions), and add your own questions and sections, each scored as Yes is good, Yes is a red flag, or context only. It applies to every vendor the next time their questionnaire is opened, on the vendor's page, in the vendor profile, in the intake score and in what Claude is asked to fill. A control whose questions are all turned off is left out of the control score, and **Reset to built-in** goes back to the original;
  - progress tracking, autosave in the vendor's browser, prompts for comments on unfavourable answers, an attestation, and Print / Save as PDF;
  - **saved straight into the vendor profile** (hosted mode): **Create link** gives the vendor a private link, shown once. It lasts 14 days, ends when the questionnaire is submitted, can be turned off at any time, and each vendor has one at a time. The form starts empty unless the analyst shares answers on file. The vendor never sees the app – the link opens their questionnaire and autosaves to your workspace as they go, from any device. Documents they attach are stored with it. When they click **Submit**, their answers, documents and follow-up replies appear in the vendor profile the next time you open it (the vendor list shows *in progress* or *response submitted*), with no files to email or import. The full questionnaire is also shown inside the vendor profile, where you can answer or correct any question yourself (marked as yours);
  - in demo mode, or with an old link, the vendor downloads a response file and emails it back instead, and **Import response** loads it: it shows an intake score and the answers needing attention, fills in the 15-control questionnaire (all mapped answers Yes → Yes, all No → No, mixed → Partial), raises data sensitivity to match the declared data types, and gives the full response to the AI vendor review.
  - **✨ Fill answers from my documents** (hosted mode) – once a vendor attaches documents, Claude fills the questions they haven't answered, showing the passage each answer came from, and flags any of the vendor's own answers that their documents contradict. The vendor reviews every suggestion before attesting; answers they keep are marked as Claude-suggested in the response you import. It works through the invite token in the link from **Copy link for vendor** (valid 30 days, 5 AI runs, counted against your workspace's AI allowance), so vendors need no account.
  - **Documentation instead of answers** – vendors can attach up to 5 documents (SOC 2 report, ISO certificate, policies, whitepaper, a previous questionnaire; PDF, Excel (.xlsx), TXT, Markdown or CSV, 20 MB total). Excel workbooks, such as a completed SIG or SIG Lite, are converted to CSV in the browser, keeping every column including follow-up history. They're embedded in the response file, and the vendor may leave questions the documents cover unanswered.
  - **✨ Fill from documents** (in the vendor editor, using your own API key) – Claude reads the attached documents, or ones you add with **Add documents** when a vendor emails documentation instead of a questionnaire, and fills the unanswered questions, each with a supporting quote and source file. It reads completed questionnaires critically: answers that contradict each other, or follow-up replies that don't address the question, are marked Unknown with the reason. It never overwrites the vendor's own answers: where the documents contradict one, it's listed as a disagreement. You can review and change every AI-filled answer before saving, and the AI vendor review is told which answers came from the vendor, from Claude or from you. Documents are held in memory only (browser storage is too small for them); re-import the response file to use them again.
- **Executive briefing** – a designed, board-ready briefing: a cover with the overall posture and a one-line headline, KPI tiles, inherent vs residual heat maps, a risk-reduction chart (inherent → residual per risk), top-risk cards with why each matters and the recommended action, systemic themes, risks by category, third-party risk with vendors by tier, a three-phase 90-day roadmap with owners, and scores worth revisiting. Every number and chart is calculated from the register; Claude writes the narrative as structured data. Without an API key you still get the data-only briefing. **Print / save PDF** prints just the briefing, and **Copy as text** gives a Markdown version for email. Set your organisation name in Settings to brand the briefing (it's also shown on vendor questionnaire links).
- **Ask the analyst** – a chat assistant that answers questions with your register and vendors as context.
- **Offline mode** – without an API key, rule-based heuristics still give baseline risk and vendor assessments.

## Running

Open `index.html` through any static server, e.g.

```bash
python3 -m http.server 8000
# then visit http://localhost:8000/
```

Then go to **Settings**, paste an Anthropic API key, and optionally **Load sample data** – it adds sample risks (three with logged exceptions), vendors, five ad-hoc risk assessments and a threat risk assessment, so every tab has something to show.

## Two modes

| | **Hosted (production)** | **Demo** |
|---|---|---|
| Turned on by | `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY` in `config.js` | leaving them empty |
| Sign-in | Email + password with mandatory authenticator-app MFA | none |
| Data | Supabase PostgreSQL, one isolated workspace per customer, row-level security | this browser's `localStorage` |
| Users | Owner / Admin / Analyst / Viewer roles (viewers see only the risks they own by default – untick **Only risks I own** to see all – and don't see the Vendors or AI analyst tabs; the database also blocks them from vendor records, vendors' questionnaire responses and documents, and the executive briefing), member profiles (name, title, department, phone), invitations, audit log | single user |
| AI | Server-side function with the API key as a secret, per-workspace quotas and usage logging | the user's own key, called from the browser |

Set up hosting with [`docs/deploy.md`](docs/deploy.md), or the beginner-friendly [step-by-step guide for Mac](docs/deploy-step-by-step-mac.md). Security controls are described in [`SECURITY.md`](SECURITY.md).

## How the AI works

- Every AI task (risk assessment, vendor review, briefing, document fill, chat) is defined once in `ai-tasks.js`: its system prompt, structured-output JSON schema, token limit and the minimum role allowed to run it. The server function uses the same file (copied to `supabase/functions/_shared/`), so clients choose a task but can't change its instructions.
- Model `claude-opus-5-5` by default, with structured outputs so results are always well-formed, streaming to avoid timeouts, and server-side refusal fallbacks (`fallbacks: "default"`), since security topics can occasionally trip safety classifiers.
- In hosted mode the browser calls `supabase/functions/ai`, which checks the session, MFA, role, rate limit and monthly quota before calling Claude, then records token usage.

## Privacy and security notes

- **Hosted mode:** see [`SECURITY.md`](SECURITY.md). In short: mandatory MFA, row-level security enforcing workspace isolation and roles, an append-only audit log, the AI key kept server-side, a strict Content Security Policy and pinned dependencies.
- **Demo mode:** risks and vendors stay in this browser's `localStorage`, and AI features send the register to `api.anthropic.com` with your own key. The key is kept in `sessionStorage` by default, or `localStorage` if you tick “Remember”. Use a dedicated key with a spend limit and avoid shared machines. Don't use demo mode for real customer data.
